Additional consulted implementation references
  Linux v6.12 drivers/usb/host/xhci.c, xhci_update_hub_device:
  https://raw.githubusercontent.com/torvalds/linux/v6.12/drivers/usb/host/xhci.c
  GPL-2.0, Copyright 2008 Intel Corp., author Sarah Sharp.
  src/reactos/usb_extensions.cpp uses version-correct hub-context command choice.
  src/reactos/runtime_power.cpp also follows the native command-ring lifetime
  requirement checked against xhci_save_registers, xhci_clear_command_ring and
  xhci_set_cmd_ring_deq: empty command-ring reinitialization and aligned CRCR reload
  before restore. No Linux API or runtime is linked.
  Transfer/event semantics were cross-checked with Linux xhci-ring.c and then
  verified against Intel document625472 revision1.2b, sections4.6.9/4.11.2.4:
  https://cdrdv2-public.intel.com/625472/625472_xHCI_Rev1_2b.pdf
  TD Size counts unsent packets across a partial packet split, and Stopped Short
  Packet reports an actual-byte accumulator rather than an ordinary residual.
  Physical AMD qualification also exposed the required empty-ring Force Stopped
  Event in section4.6.9: code27 precedes Stop Endpoint command completion even
  without a queued TD. The native owner validates its stop generation and ring
  bounds; only the actual command/dequeue sequence establishes DMA retirement.
  Linux v6.12 xhci-ring.c handle_tx_event independently handles empty TD lists:
  https://raw.githubusercontent.com/torvalds/linux/v6.12/drivers/usb/host/xhci-ring.c
  The specification is consulted, not redistributed.

Repository-owned ReactOS compatibility
  compat/reactos/usbstor-transport.patch and usbhub-superspeed.patch retain their
  original source notices and add C++ hooks for bounded BOT byte results, native
  SuperSpeed/hub contracts and joined class-device cleanup. Source baseline hashes
  are in evidence/m07-usbstor-patch-inputs.json and m08-usbhub-patch-inputs.json.
  compat/reactos/disk-shutdown.patch preserves cache/unlock failure through final
  shutdown completion. The separately linked disk.sys source and its new hook use
  MS-PL, matching drivers/storage/class/disk/license.txt. A preserved copy is at
  compat/reactos/disk/license.txt; baseline hashes are in m07-disk-patch-inputs.json.
  This module does not link GPL host-controller/core helpers. Existing classpnp
  storage CDB/FUA/flush ordering is reused. Owned staging builds do not alter the SDK
  or install class modules. Generated native artifacts retain their separate scope.
  The HIDUSB cancellation compatibility retains genuine NT/USBD cancellation
  results instead of asserting or inventing success. Original driver authors
  Michael Martin and Johannes Anderwald and GPL notices remain in the staged C
  source; evidence/m10-hidusb-patch-inputs.json pins its inputs.
  Boot-usage compatibility forwards actual disk-to-controller paging-path
  notifications; evidence/m10-boot-patch-inputs.json pins those additional inputs.
  Child removal flushes only its live device handle before retirement. The
  previous USBHUB-wide NULL flush cancelled unrelated sibling HID requests.

  docs/imported/rtl8125/STYLE_GUIDE.md and ARCHITECTURE.md are unchanged snapshots
  from the RTL8125 project. Their original network and GPU inventories do not
  describe this xHCI implementation. evidence/document-imports.json pins them.

Host operations
  Inventory reads DMI and PCI sysfs identity/resources/root-bus metadata only.
  It does not open resourceN, detach/reset a USB controller, alter a PCI binding,
  modify the external SDK or write any host disk/USB stick. Linux xhci_hcd remains
  bound after guarded physical sessions. Inventory alone establishes no transfer
  success; actual selected-controller results are recorded separately in M11.
